EN 16931 · Peppol BIS Billing 3.0

einvoice-validator

Validation of European e-invoices against the official published validation artefacts, in pure Rust: no JVM, no C library, no FFI. Built to run the official stylesheets unchanged, with exact decimal arithmetic, and to give the same report as Saxon-HE, rule by rule.

Pre-alpha: not usable yet. It does not validate invoices yet, and nothing is published on crates.io.

Done: the XPath 2.0 parser, the XSLT loader, the XPath 2.0 atomic values with exact decimals, and the CEN UBL 1.3.17 test corpus with its Saxon-HE results. In progress: the XPath evaluator, the XSLT executor, UBL schema validation. Follow the tracking issues.

What it is

The business rules of EN 16931 and of Peppol BIS Billing 3.0 are published by CEN and OpenPeppol as Schematron, which validators run compiled to XSLT 2.0 stylesheets. einvoice-validator is an XSLT 2.0 and XPath 2.0 engine, written in Rust, built to run those stylesheets as they are published.

  • The official artefacts are the rules. No rule is translated into Rust by hand. The CEN artefacts are vendored byte for byte, with their checksums.
  • A closed subset. The engine implements the XSLT and XPath the official stylesheets use, nothing more. Anything else is refused when the stylesheet is loaded, never skipped.
  • Exact numbers. xs:decimal and xs:integer are arbitrary precision, as the amount and total rules require; no floating-point stand-in.
  • The reference engine decides. The goal is the report Saxon-HE produces for the same document: same fired rules, same failed asserts and successful reports, with the same id, flag and location, in the same order (#3).
  • Pure Rust. No Java runtime, no C library, no FFI. A library and command-line tool (#10) and a WebAssembly build (#9) are planned.

Why run the official stylesheets

The validation artefacts are the reference definition of the rules. Running them unchanged means a new release of the rules is new data to vendor and test, not code to rewrite, and a result can always be traced back to the published rule that produced it.

Quality

  • Reference results. 1179 cases from the official CEN UBL 1.3.17 examples, test files and unit tests, each with the SVRL report Saxon-HE 9.9.1-8 produces. CI runs Saxon again and the results must not change; they are cross-checked against the expectations of the official unit tests, with no disagreement. The atomic-value operations already match Saxon-HE on over 5000 test cases.
  • Integrity. Vendored artefacts are checked against their SHA-256 sums; Saxon-HE, used only in tests, is downloaded from Maven Central and its checksum verified.
  • Lints. Every warning is an error; clippy all and pedantic are denied; unwrap, expect and panic are denied outside tests; unsafe code is forbidden.
  • Tests. Unit, golden and property-based tests (proptest); on Linux for every push to main, also on macOS and Windows for pull requests.
  • Supply chain. Toolchain pinned (Rust 1.99.1), Cargo.lock committed and every cargo command --locked; licences, advisories and sources checked by cargo-deny; GitHub Actions pinned by commit SHA, linted by actionlint and audited by zizmor; signed commits.
  • Same checks everywhere. CI and a local run use the same script: see Build and test.

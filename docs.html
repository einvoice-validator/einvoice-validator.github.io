Build and test

For contributors. There is nothing to install yet: einvoice-validator is pre-alpha, does not validate invoices, and no crate is published.

Requirements

  • rustup, Git and Bash. The toolchain is pinned in rust-toolchain.toml (Rust 1.99.1 with rustfmt and clippy); scripts/check.sh installs it when it is missing.
  • Optional: cargo-deny, actionlint and zizmor. Without one of them its check prints SKIPPED; CI installs all three at pinned versions.
  • For the reference oracle only: Java (CI uses Temurin 21) and network access the first time, to download Saxon-HE.

Build from source

git clone https://github.com/einvoice-validator/einvoice-validator.git
cd einvoice-validator
# install the pinned toolchain if needed
scripts/check.sh toolchain
cargo build --workspace --locked

Cargo.lock is committed; every cargo command in the checks uses --locked.

Checks

CI and a local run execute the same script, with the same flags. Every warning is an error.

# every job
scripts/check.sh
# selected jobs
scripts/check.sh clippy test
# only install the pinned toolchain
scripts/check.sh toolchain

Tests

# everything
cargo test --workspace --all-features --locked
# one crate
cargo test -p einvoice-xdm --locked
# the tests of a crate whose path contains a name
cargo test -p einvoice-xdm --locked every_case
# corpus checks, no Java needed
cargo test -p xtask --locked

Besides unit tests: golden tests against results produced by Saxon-HE, and property-based tests with proptest.

Test corpus and reference oracle

artefacts/ holds unmodified copies of the official validation artefacts, corpus/ the test cases derived from them and, for each case, the SVRL report Saxon-HE 9.9.1-8 produces. The format is described in corpus/README.md.

# vendored files match artefacts/*/SHA256SUMS
cargo xtask manifest
# the corpus re-derived from artefacts/ matches the committed one
cargo xtask corpus
# Saxon results vs the expectations of the official unit tests
cargo xtask crosscheck
# Saxon-HE from Maven Central, checksum verified, into target/oracle/saxon/
scripts/fetch-saxon.sh
# Saxon-HE on all 1179 cases: results must equal the committed ones
cargo xtask oracle
# all of the above, then the atomic-value oracle of einvoice-xdm
scripts/check.sh oracle

--write regenerates instead of checking (manifest, corpus, oracle). cargo xtask oracle also takes --java JAVA and --saxon JAR; scripts/check.sh oracle reads them from the JAVA and SAXON_JAR environment variables. Without Java, scripts/check.sh oracle runs the manifest, corpus and cross-check and skips the Saxon run (in CI it fails instead). cargo test covers the manifest, extraction and cross-check without Java.

Repository layout

crates/einvoice-xpath
Parser and syntax tree for the XPath 2.0 subset of the official stylesheets.
crates/einvoice-xdm
Atomic values of the XPath 2.0 data model: exact xs:decimal, xs:integer, xs:double, dates, casts, comparisons, regular expressions, with the behaviour of Saxon-HE 9.9.
crates/einvoice-xslt
Loader for the XSLT 2.0 subset: templates, modes, priorities, functions, variables and instructions; anything outside the subset is a load error.
crates/einvoice-validator
The library crate; no validation code yet.
xtask
Repository tooling behind cargo xtask: manifest, corpus, oracle, cross-check.
artefacts
Official validation artefacts, unmodified, with their licence and SHA256SUMS.
corpus
Test cases and their Saxon-HE results, one directory per rule set.
scripts
check.sh, fetch-saxon.sh and the other repository scripts.
